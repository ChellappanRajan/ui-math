Calculus of a Card Grid

Shu Ding's post turned a whole React dashboard into a math function and showed 11 tricks. Here are the same 11 tricks on the smallest dashboard possible: six cards in a grid. Drag every slider. Nothing here is a screenshot; it is all computed live.

Start here

The one function we play with

A browser page is just a machine: you feed it numbers (window width, gap, padding) and it gives you back positions and sizes. In math we call that a function: UI = f(props).

The HTML
<div class="grid">
  <div><b>Revenue</b>...</div>
  <div><b>Signups</b>...</div>
  ... 6 cards in total
</div>
The CSS
.grid {
  display: grid;
  grid-template-columns:
    repeat(auto-fill, minmax(120px, 1fr));
  gap: 16px;
  padding: 16px;
  max-width: 900px;
}
.grid > div { height: 70px; }

In plain words: "fit as many 120px-wide cards in a row as you can, then stretch them to fill the row; never let the box get wider than 900px". The same rules written as math:

W = window width                        (the prop we change)
c = min(W, 900)                         box width, capped at 900
need(n) = 2·16 + n·120 + (n−1)·16       width needed to fit n cards
n = 1 + step(c − need(2)) + … + step(c − need(6))   number of columns
cardWidth = (c − 32 − (n−1)·16) / n
rows = ⌈6 / n⌉
H = 32 + rows·70 + (rows−1)·16          page height

step(x) is a light switch: 0 when x is negative, 1 otherwise. Each switch flips on when there's room for one more column. That's the only "if" in the whole layout.

Glossary

Math words you'll meet

step(x)A light switch. Jumps from 0 to 1 at x = 0.
sigmoid(x)A dimmer switch. Slides smoothly from 0 to 1 around x = 0.
derivative f′Speed. "If I nudge the input by 1, how much does the output move?"
gradientAll the speeds together: which way to turn each knob to improve a score.
interval [a, b]"Every number from a to b". Do math on whole ranges at once.
integral ∫Adding up infinitely many tiny pieces, e.g. an exact average.
Fourier transformWriting any wiggly line as a sum of simple waves.
complex number a + biA number with a second, "imaginary" direction.
Trick 1 of 11

Velocity

If the window gets 1px wider, how far does each card move, and how much does it grow?

∂x/∂W = (how much x moves) / (how much W moved)
cardWidth = (W − 32 − (n−1)·16) / n   →   ∂cardWidth/∂W = 1/n
card in column k sits at x = 16 + k·(cardWidth + 16)  →  ∂x/∂W = k/n
Above 900px the box stops growing and just re-centers: every card moves 0.5.

In CSS termsEach card shows → its sliding speed and ↔ its growing speed. We get them from the formula in one pass. No rendering twice and comparing.

Trick 2 of 11

Gradient

Goal: on phone, tablet and laptop, no card narrower than 140px (so descriptions aren't cut off), and pages as short as possible. Can math pick the gap, padding and card size for us?

gap
padding
min card width
score (lower is better) 
score = Σ (page height)/100  +  Σ max(0, 140 − cardWidth)
gradient = ( ∂score/∂gap, ∂score/∂padding, ∂score/∂cardMin )
new knobs = old knobs − small step × gradient        ← "walk downhill"

In CSS termsRed outlines mark cards under 140px. Gradient descent is the same idea used to train AI models, here used to tune gap, padding and minmax(…px, 1fr). A light switch has no slope, so we use the dimmer version (trick 6) while searching. The search starts very soft and sharpens step by step, so it can see breakpoints from far away. We measure each slope by nudging a knob 0.5px; the original project reads it exactly from the formula.

Trick 3 of 11

Proof

Can we be 100% sure the page stays under a height limit for every window width in a range, not just the few we tested?

Step 1: run every formula on the whole range at once
Step 2: if the answer is "maybe", cut the range in half and try again
proven OK everywhereproven to fail everywhere
Interval arithmetic: do the math on [lowest, highest] instead of one number.
[a, b] − 32 = [a − 32, b − 32]       min([a,b], 900) = [min(a,900), min(b,900)]
Every step keeps the true answer inside the range, so if the
largest possible height ≤ limit, it's proven for infinitely many widths.

In CSS termsA normal test checks 3 or 4 screen sizes. This checks every width between the two sliders, including 517.3px and every other width you'd never think to test.

Trick 4 of 11

Discontinuity

Where exactly does the layout jump or change behaviour, without dragging the window around?

jump: a card wraps to a new rowbend: the box hits max-width
A jump in f(x): the line breaks.       → a card moves to another row
A jump in f′(x): the line bends.        → something hit a limit (max-width)
Jumps happen exactly where a step() flips: c = need(n), solved by hand.

In CSS termsOur CSS has zero @media breakpoints, yet the layout still has 5 jumps and 1 bend. The math finds the real visual breakpoints, not just the ones someone wrote down.

Trick 5 of 11

Geodesic

We change two props at once: window 650 → 1000px and max-width 900 → 500px. Which route between them makes the fewest cards jump?

Every design is a point (W, maxWidth) on this map. Shading = number of columns.
Crossing a shade border = a jump. The geodesic is the route with the fewest jumps.
The straight line isn't always best: it can cross the same border twice.

In CSS termsChanging max-width first, then the window, keeps the cards calm. Changing both together makes cards wrap and unwrap.

Trick 6 of 11

Smoothness

What if we replace every light switch with a dimmer?

step(x)    = 0 or 1              ← cards teleport
sigmoid(x) = 1 / (1 + e^(−x/τ))  ← cards glide
weight of "n columns" = s(n) − s(n+1), then blend the n-column layouts

In CSS termsThere is no transition or animation in this demo. The movement comes only from softening the math. Turn the checkbox off to see cards jump.

Trick 7 of 11

Linearity

Can we skip the layout calculation while the user resizes?

f(x) ≈ f(a) + f′(a)·(x − a)       ← the tangent-line formula
Between two breakpoints the cards move in straight lines, so this is exact.
Dashed outlines = predicted spot.  Solid cards = real layout.

In CSS termsLay out once, remember the speeds, and predict every resize frame with one multiply. Only redo the full layout after crossing a breakpoint.

Trick 8 of 11

Signal

Page height across window widths is a wiggly line, like a sound. What if we compress it like an MP3 or JPEG?

real page height H(W)rebuilt from a few waves
H(W) = a₀ + a₁·wave₁ + a₂·wave₂ + …     (Fourier transform)
Keep only the biggest waves → a blurry, "JPEG-ish" layout.

In CSS termsNot useful, just fun. The ripples near each jump are the same effect that makes JPEG photos fuzzy around sharp edges.

Trick 9 of 11

Average

Given who actually visits, how tall is the page on average?

Exact average page height
average = ∫ H(w) · ρ(w) dw          ρ = how common each width is
H is flat between breakpoints, so the integral is just
average = Σ  (height of piece) × (share of visitors in that piece)

In CSS termsYour analytics tell you who visits. This gives the exact average page those visitors see. No sampling, no guessing.

Trick 10 of 11

Imaginary

What happens if the window width is a complex number, like 696 + 30i px?

W = a + b·i       Feed it into the dimmer version from trick 6.
Real part of each result      → where the card is drawn
Imaginary part of each result → how high it "lifts" (shadow + scale)
Imaginary part ≈ (imaginary nudge) × (speed), so fast movers lift. We subtract
the steady sliding, so only cards jumping across a breakpoint rise, pass over, and land.

In CSS termsLift is drawn with box-shadow and transform: scale(), but the amount comes from the math. Far from a breakpoint cards barely lift; the card that travels furthest at the wrap lifts the most.
